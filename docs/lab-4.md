# Масштабирование изображения

Первая часть — собственные алгоритмы ближайшего соседа и билинейной интерполяции в `src/image/resample.ts`. Функция `resizeRaster` работает с массивом RGBA, возвращает новый массив и не обращается к canvas. По умолчанию выбрана билинейная интерполяция. Методы и их описания собраны в одном реестре для дальнейшего расширения.

Координаты сопоставляются по центрам пикселей: (x + 0,5) × исходная ширина / новая ширина − 0,5. За границами используются крайние пиксели. Ближайший сосед копирует все четыре компоненты, включая скрытый цвет. Билинейный метод смешивает четыре соседних пикселя с весами расстояния; RGB сначала взвешивается по альфе, чтобы цвет прозрачного соседа не давал ореола. При нулевой суммарной альфе результат — прозрачный чёрный. При неизменном размере возвращается точная копия, включая скрытые значения.

Интерполяция выполняется в пространстве хранимых компонентов sRGB, без дополнительной линеаризации. Билинейный метод не является усреднением всей площади пикселя при сильном уменьшении и не гарантирует отсутствие алиасинга.

До выделения памяти проверяются целые положительные размеры, длина исходного массива и лимиты проекта: 24 миллиона пикселей и 16384 по стороне. Для буфера просмотра сверх этих ограничений используется отрисовка видимого фрагмента, описанная ниже.

Из референса изучены `utils/resize.ts` и `utils/scaleImage.ts`; файлы референса не изменялись. Новая реализация использует независимый от DOM интерфейс, сопоставление центров и обработку прозрачности.

Вторая часть: алгоритмы подключены к просмотру. Диапазон масштаба — 12–300 процентов, значение и выбор метода находятся в информационной панели. По умолчанию используется билинейная интерполяция; изменение масштаба не меняет пиксели документа и скачиваемого файла. Canvas содержит рассчитанные пиксели в размере отображения, CSS не выполняет масштабирование изображения.

При загрузке и в режиме «Вписать» масштаб рассчитывается по доступной области с отступом минимум 50 пикселей с каждой стороны. Маленькие изображения автоматически не увеличиваются. Если большое изображение не помещается при 12 процентах, сохраняется минимальный масштаб и появляется прокрутка. Это ограничение не позволяет одновременно гарантировать полное вписывание и нижнюю границу 12 процентов во всех размерах окна.

Для отрисовки до 24 Мп создаётся полный буфер просмотра. Если увеличение превышает этот предел или 16384 пикселя по стороне, создаётся только видимый фрагмент. Фрагменты рассчитываются в координатах полного увеличенного изображения, поэтому прокрутка не меняет интерполяцию на их границах. Пипетка использует геометрию полного изображения и читает исходный пиксель, независимо от буфера просмотра.

Проверки охватывают точные значения обоих методов при 300 процентах, совпадение фрагмента с частью полной отрисовки, отображение 4K при 300 процентах, прокрутку и пипетку, сохранение без изменения размеров, отступы и минимальный масштаб.

Третья часть: отдельный диалог изменения размера на общем компоненте Modal с нативным dialog, возвратом фокуса и отменой по Escape. Показаны размеры и число пикселей до и после операции, единицы пиксели/проценты, связь пропорций и выбор интерполяции. Подсказка метода доступна мышью, клавиатурой и нажатием. Escape сначала скрывает открытую подсказку, следующее нажатие закрывает диалог.

Проценты отсчитываются от текущего изображения при открытии инструмента. Диапазон процентов — 0,01–10000, результат округляется до целых пикселей. Нулевой результат, нецелые пиксельные размеры, пустые поля и превышение лимитов блокируют применение. Связь пропорций пересчитывает вторую сторону по исходному для операции соотношению, с округлением до ближайшего пикселя. Отмена не изменяет документ. Применение создаёт новый массив своим алгоритмом и сохраняет текущий процент просмотра. Исходные метаданные не переписываются; изменённый размер дополнительно отображается в информационной панели.

Четвёртая часть: заключительные совместные проверки выполнены на готовой локальной сборке в Chromium. Пройдены 152 модульных и 72 браузерных теста; сборка, TypeScript и ESLint завершены без ошибок.

Дополнительно проверена цепочка «уровни → отключение канала → масштаб 200% → изменение размера → пипетка». Видимость каналов и процент просмотра сохраняются, миниатюры и координаты пипетки соответствуют изменённому изображению, гистограмма считает новое количество пикселей. Повторное изменение размера начинает расчёт процентов от текущих размеров. Экспорт после двух изменений размера проверен для PNG, JPG и GB7 с чтением заголовка скачанного файла и повторной загрузкой. Окно изменения размера и подсказка проверены на экране 640 × 360, отмена возвращает управление основному интерфейсу.

Публикация четвёртой работы и проверка обновлённого Render остаются отдельным шагом после согласования коммита и пуша. Результаты выше относятся к локальной сборке; Firefox и Safari в этот прогон не входили.
