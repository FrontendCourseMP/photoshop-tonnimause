# Масштабирование изображения

Первая часть — собственные алгоритмы ближайшего соседа и билинейной интерполяции в `src/image/resample.ts`. Функция `resizeRaster` работает с массивом RGBA, возвращает новый массив и не обращается к canvas. По умолчанию выбрана билинейная интерполяция. Методы и их описания собраны в одном реестре для дальнейшего расширения.

Координаты сопоставляются по центрам пикселей: (x + 0,5) × исходная ширина / новая ширина − 0,5. За границами используются крайние пиксели. Ближайший сосед копирует все четыре компоненты, включая скрытый цвет. Билинейный метод смешивает четыре соседних пикселя с весами расстояния; RGB сначала взвешивается по альфе, чтобы цвет прозрачного соседа не давал ореола. При нулевой суммарной альфе результат — прозрачный чёрный. При неизменном размере возвращается точная копия, включая скрытые значения.

Интерполяция выполняется в пространстве хранимых компонентов sRGB, без дополнительной линеаризации. Билинейный метод не является усреднением всей площади пикселя при сильном уменьшении и не гарантирует отсутствие алиасинга.

До выделения памяти проверяются целые положительные размеры, длина исходного массива и лимиты проекта: 24 миллиона пикселей и 16384 по стороне. Ограничения буфера просмотра на масштабе до 300 процентов будут рассмотрены при подключении к холсту.

Из референса изучены `utils/resize.ts` и `utils/scaleImage.ts`; файлы референса не изменялись. Новая реализация использует независимый от DOM интерфейс, сопоставление центров и обработку прозрачности.

Вторая часть: алгоритмы подключены к просмотру. Диапазон масштаба — 12–300 процентов, значение и выбор метода находятся в информационной панели. По умолчанию используется билинейная интерполяция; изменение масштаба не меняет пиксели документа и скачиваемого файла. Canvas содержит рассчитанные пиксели в размере отображения, CSS не выполняет масштабирование изображения.

При загрузке и в режиме «Вписать» масштаб рассчитывается по доступной области с отступом минимум 50 пикселей с каждой стороны. Маленькие изображения автоматически не увеличиваются. Если большое изображение не помещается при 12 процентах, сохраняется минимальный масштаб и появляется прокрутка. Это ограничение не позволяет одновременно гарантировать полное вписывание и нижнюю границу 12 процентов во всех размерах окна.

Для отрисовки до 24 Мп создаётся полный буфер просмотра. Если увеличение превышает этот предел или 16384 пикселя по стороне, создаётся только видимый фрагмент. Фрагменты рассчитываются в координатах полного увеличенного изображения, поэтому прокрутка не меняет интерполяцию на их границах. Пипетка использует геометрию полного изображения и читает исходный пиксель, независимо от буфера просмотра.

Проверки охватывают точные значения обоих методов при 300 процентах, совпадение фрагмента с частью полной отрисовки, отображение 4K при 300 процентах, прокрутку и пипетку, сохранение без изменения размеров, отступы и минимальный масштаб. Следующие части: диалог изменения размера, заключительные совместные проверки и публикация.
